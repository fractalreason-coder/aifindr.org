# AI 중고차 알선 에이전트 — 서비스 디자인 (v0.1 초안)

> 상태: 초안 / 작성일: 2026-09-30
> 전제: 카모드(Carmode) 재고 = 매칭 대상. 딜러 정보는 고객에게 비공개. 딜러 정보 문의·추가 할인은 **뮤즈(가칭)** 로 연결.

---

## 1. 한 줄 정의

고객이 대화로 원하는 차종과 상황을 말하면, AI가 카모드 재고에서 맞는 차량을 골라 보여 주고 **알선(계약 성사까지의 진행)** 을 대행한다. 딜러 정보와 추가 할인은 **뮤즈(사람 상담/딜 데스크)** 가 맡는다.

## 2. 핵심 원칙

1. **대화 우선**: 필터·검색 폼이 없다. 질문 몇 개로 조건을 좁힌다.
2. **딜러 비공개**: 딜러명·상사명·연락처·주소·매물 원본 링크는 고객 화면과 AI 응답에 절대 나오지 않는다.
3. **뮤즈 에스컬레이션**: 딜러 정보 요청, 가격 흥정, 추가 할인 요청은 AI가 처리하지 않고 "뮤즈에게 물어보세요"로 안내한다.
4. **할인 재원 = 알선 수수료 분배**: 할인은 알선 수수료 안에서 뮤즈가 결정한다. AI는 할인 금액을 약속하지 않는다.
5. **사실만 말한다**: 재고·가격·사고이력은 카모드 데이터에 있는 값만 말한다. 없으면 "확인 후 안내"라고 한다.

## 3. 사용자 여정

```
[진입] → [1 대화 인테이크] → [2 매칭·추천] → [3 관심 차량 확정]
      → [4 알선 접수(본인확인·동의)] → [5 알선 진행(AI+운영)] → [6 계약·출고]
                      ↘ (언제든) 딜러 정보/할인 요청 → [뮤즈 연결]
```

### 3.1 대화 인테이크 (슬롯 채우기)

한 번에 1~2개씩만 묻는다. 이미 말한 정보는 다시 묻지 않는다.

| 구분 | 슬롯 | 필수 |
|---|---|---|
| 차량 | 차종/차급/브랜드, 연식 범위, 주행거리 상한, 연료, 색상 | 차종·예산 |
| 예산 | 총예산 또는 월 납입, 결제 방식(현금/할부/리스) | 예산 |
| 상황 | 용도(출퇴근/가족/영업), 인원, 첫 차 여부, 급한 정도, 지역(수령·점검 가능 지역) | 용도 |
| 제약 | 무사고 선호, 금연차, 렌터카 이력 제외, 성능점검 등급 | 선택 |
| 거래 | 트레이드인(보유 차량) 여부, 인수 희망 시기 | 선택 |

- 모호한 요청("가성비 좋은 SUV")은 예산·용도 질문으로 구체화한다.
- 조건이 재고에 없으면 어떤 조건을 완화하면 몇 대가 나오는지 제안한다. ("연식 1년 늘리면 7대")

### 3.2 매칭·추천

- 카모드 재고를 하드 조건(예산, 연료, 지역)으로 거른 뒤 소프트 조건으로 점수화한다.
- 결과는 **3~5대** 카드로 제시한다. 각 카드에 "왜 맞는지" 한 줄 이유를 붙인다.
- 카드 노출 필드: 차종·연식·주행거리·가격·성능점검 요약·사고/침수 여부·사진·지역(시·군 단위). 딜러 관련 필드는 없다.
- 고객이 "더 싸게", "비슷한 다른 차"를 말하면 재매칭한다.

### 3.3 알선 접수

- 고객이 "이 차로 진행"을 선택하면 본인 확인, 개인정보 제공 동의, **알선 대행 위임 및 수수료 안내 동의**를 받는다.
- 이후 AI가 진행 상황(재고 확인 → 조건 확정 → 시승/점검 일정 → 계약)을 안내하고, 운영자가 딜러와 실제 연락을 수행한다.

### 3.4 뮤즈 연결

트리거 예시:
- "딜러가 누구예요 / 어느 상사예요 / 전화번호 알려줘"
- "더 깎아줘 / 할인 되나요 / 다른 데는 더 싸던데"
- "직접 만나서 보고 싶다 / 매장 위치"

AI 응답 원칙:
> 딜러 정보는 공개하지 않아요. 딜러 정보가 궁금하시거나 추가 할인을 원하시면 **뮤즈**에게 물어보세요. 알선 수수료 안에서 할인을 도와드립니다.

이때 AI는 "뮤즈 상담 연결" 버튼과 함께, 대화 요약(조건, 관심 차량)을 뮤즈에게 넘긴다. 고객은 처음부터 다시 설명하지 않아도 된다.

## 4. 시스템 구조

```
고객 채팅 UI (Nuxt)
     │
Chat API (Cloudflare Worker)  ──  세션/대화 저장 (D1)
     │
Agent Orchestrator (Claude, tool use)
     ├─ tool: search_inventory(criteria)     → 카모드 어댑터 → 마스킹 레이어
     ├─ tool: get_vehicle(vehicle_ref)       → 마스킹 레이어
     ├─ tool: start_brokerage(vehicle_ref)   → 알선 워크플로 (상태머신)
     ├─ tool: handoff_to_muse(reason, summary)
     └─ tool: save_customer_profile(slots)
     │
운영 콘솔 (뮤즈/알선 담당): 대화 요약, 딜러 원본 정보, 할인 승인, 딜러 연락 기록
```

### 4.1 마스킹 레이어 (가장 중요)

- 카모드 원본 → **공개용 Vehicle** 로 변환하는 단일 통로. 딜러 필드는 여기서 제거한다.
- AI 도구는 마스킹된 결과만 받는다. 모델이 딜러 정보를 아예 보지 못하게 해서 프롬프트 인젝션·유출을 구조적으로 막는다.
- 고객 식별용 `vehicle_ref`는 내부 ID가 아닌 세션 범위의 불투명 토큰을 쓴다.
- 딜러 원본 매핑(`vehicle_ref → dealer`)은 운영 콘솔 서버에서만 조회한다.

### 4.2 알선 워크플로 상태

```
INTAKE → MATCHED → SELECTED → CONSENTED → DEALER_CONTACTED
       → CONDITIONS_CONFIRMED → VISIT/INSPECTION → CONTRACT → DELIVERED
                                              ↘ DROPPED (사유 기록)
```

각 전이는 알림(카카오 알림톡/SMS)과 감사 로그를 남긴다. `DEALER_CONTACTED` 이후는 운영자 수동 단계를 포함한다(MVP).

### 4.3 데이터 모델 (요약)

| 테이블 | 핵심 컬럼 |
|---|---|
| `customers` | id, 연락처(암호화), 동의 이력 |
| `conversations` | id, customer_id, slots(JSON), status, summary |
| `messages` | conversation_id, role, content, tool_calls |
| `recommendations` | conversation_id, vehicle_ref, score, reason |
| `brokerages` | id, customer_id, vehicle_ref, state, fee_terms, discount_amount, muse_owner |
| `muse_handoffs` | conversation_id, reason, summary, assigned_to, resolved_at |
| `audit_logs` | actor, action, target, at (딜러 정보 조회 이력 포함) |

## 5. 프롬프트/에이전트 가드레일

- 시스템 프롬프트 규칙: 딜러 관련 질문은 도구를 호출하지 않고 뮤즈 안내 문구로 응답. 할인 금액·가능 여부 단정 금지. 재고에 없는 차량 언급 금지.
- 출력 필터: 응답에서 전화번호, 상호 패턴, 카모드 원본 URL을 정규식으로 한 번 더 차단.
- 대화 종료 조건: 고객 이탈 시 대화 요약을 저장하고 재방문 시 이어서 진행.

## 6. 법·정책 리스크 (출시 전 반드시 검토)

1. **딜러 정보 비공개의 적법성**: 중고차 거래에서 매매업자 정보·성능점검기록부 등 고지 의무가 있다. 계약 단계에서는 법정 서류로 딜러(매매사업자) 정보가 고객에게 전달되어야 한다. "탐색 단계 비공개, 계약 단계 법정 고지"로 설계하고 법무 검토를 받는다.
2. **알선 지위**: 알선 대행과 중개/매매 알선 관련 자동차관리법 및 조합 규정 준수 여부, 수수료 수취 방식(누구에게서 받는가) 확인.
3. **수수료·할인 표시**: 수수료 존재와 할인 조건을 고객에게 사전 고지(표시광고 관련 이슈 방지).
4. **개인정보**: 연락처·신분 정보는 최소 수집, 암호화, 보관 기간 설정.
5. **카모드 이용 조건**: 재고 데이터의 외부 노출·AI 처리 허용 범위 계약 확인.

## 7. MVP 범위 (4주 가정)

| 주차 | 내용 |
|---|---|
| 1 | 카모드 데이터 연동 방식 확정, 마스킹 레이어, 공개용 Vehicle 스키마 |
| 2 | 대화 인테이크 + 매칭 도구, 채팅 UI |
| 3 | 알선 접수·상태머신, 뮤즈 핸드오프, 운영 콘솔(최소) |
| 4 | 가드레일 테스트(딜러 유출 시도 시나리오), 파일럿 |

성공 지표: 대화 → 관심 차량 선택 전환율, 뮤즈 연결률, 알선 접수→계약 전환율, 딜러 정보 유출 사고 0건.

## 8. 확인이 필요한 질문

1. 카모드 재고 연동 수단은 API, DB, 크롤링 중 무엇인가? 실시간 재고/가격 갱신 주기는?
2. 뮤즈는 사람 상담팀인가, 별도 AI 에이전트인가, 혼합인가? (지금은 사람 + 콘솔로 가정)
3. 알선 수수료는 누구에게서 얼마를 받는가, 할인 가능 한도는?
4. 서비스는 독립 사이트인가, 카모드/조합 사이트 내 위젯인가?
5. 기존 `G 스마트 컨트랙트` 프로젝트와 연결할 부분(전자계약, 조합원 인증 등)은 무엇인가?
